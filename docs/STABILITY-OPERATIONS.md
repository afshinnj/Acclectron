# عملیات پشتیبان‌گیری و عیب‌یابی Acclectron

## پشتیبان‌گیری و بازیابی

- در تنظیمات، پوشه و تناوب پشتیبان‌گیری خودکار را تعیین کنید. برنامه حداکثر ۱۴ فایل پشتیبان زمان‌بندی‌شده را در همان پوشه نگه می‌دارد.
- برای پشتیبان‌گیری دستی از گزینهٔ «پشتیبان‌گیری همین الان» استفاده کنید.
- بازیابی فقط فایل SQLite سالم و سازگار با ساختار برنامه را می‌پذیرد. پیش از جایگزینی دیتابیس، برنامه یک snapshot از دیتابیس فعلی می‌سازد و مسیر آن را پس از بازیابی نشان می‌دهد.
- پس از بازیابی، برنامه را ببندید و دوباره باز کنید تا همهٔ نماها از دیتابیس بازیابی‌شده بارگیری شوند.
- در صورت شکست بازیابی، برنامه تلاش می‌کند دیتابیس قبلی را برگرداند. snapshot ایمنی را تا پایان بررسی نگه دارید.

## گزارش خطا

لاگ‌های فرایند اصلی در پوشهٔ `logs` زیر مسیر دادهٔ کاربر Electron ذخیره می‌شوند. فایل روزانه تا ۲ مگابایت محدود است، نسخه‌های همان روز چرخش می‌کنند و ۱۰ فایل آخر نگهداری می‌شود. خطاهای uncaught، خطاهای کنسول renderer، خطای preload و crash renderer در این لاگ ثبت می‌شوند.

برای گزارش اشکال، نسخهٔ برنامه، نسخهٔ Windows، مراحل بازتولید و لاگ مرتبط را ضمیمه کنید. فایل دیتابیس واقعی یا اطلاعات ورود را ارسال نکنید.

## بررسی محلی و CI

از ریشهٔ پروژه اجرا کنید:

```powershell
npm ci
npm run check
npm test
npm run build:portable
```

GitHub Actions همین مراحل را روی Windows اجرا می‌کند و ZIP قابل‌حمل، checksum و manifest را به‌عنوان artifact همان اجرای workflow منتشر می‌کند. Artifactها ۱۴ روز نگهداری می‌شوند.

## نسخه‌بندی دیتابیس

ساختار فعلی با migration شمارهٔ ۲ ثبت می‌شود. migrationهای بعدی را به‌صورت تغییرات افزایشی و تراکنشی به فهرست `DATABASE_MIGRATIONS` در `src/main/db/core.js` اضافه کنید؛ شمارهٔ هر migration باید یکتا و صعودی باشد. تست بازگشایی دیتابیس قدیمی را همراه migration اضافه کنید.
